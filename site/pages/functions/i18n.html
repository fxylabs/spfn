FUNCTIONS / @SPFN/I18N — INTERNATIONALIZATION RUNTIME

Words,
in context.

@spfn/i18n supplies the small runtime between your translation catalogs and your UI: interpolation, fallback lookup, server helpers, and React context. Your application keeps ownership of the words and the locale policy. A second language is cheap to allow for early and expensive to retrofit once the copy is scattered through components.

01
The boundary

The runtime translates.
Your app decides.

Catalog loading, persistence, and content stay in the consuming application, and so does the locale policy: localized routing and negotiateLocale are helpers the app chooses to call, never a default the runtime imposes. The runtime accepts plain locale → namespace → message objects and turns them into predictable translators without imposing a file layout, fetch layer, or CMS.

Server to client

Only the messages
this subtree needs.

getClientMessages() resolves selected namespaces on the server, merging fallback values first and locale-specific values second. Pass the serializable result through I18nProvider; client components call useT() without a loading flash or a second catalog request.

What's inside

The translation layer,
nothing extra.

plain catalogs

Locale, namespace, key, message — application-owned objects.
createTranslator

Translate independently of React, Next.js, or SPFN.
interpolation

Named string and number placeholders remain visible when missing.
fallback lookup

Locale-specific values override a configured fallback locale.
server registry

Configure once, then resolve namespace-scoped translators.
client messages

Serialize only selected, fully resolved namespaces.
React context

I18nProvider, useT, and useLocale for client subtrees.
typed keys

Register the catalog shape once and a mistyped key fails the compile.
qualified keys

A translator that takes the namespace from the key — useT() and getT(locale).
missing keys

onMissingKey fires when neither the locale nor the fallback has an entry.
localized routing

defineI18nRouting — a URL policy such as English at / and Korean at /ko.
locale negotiation

negotiateLocale and localeCookie for app screens with no locale in the URL.
content agnostic

No catalog loaders, date or number formatting, or plural rules.
