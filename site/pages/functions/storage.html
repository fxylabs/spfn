One interface over Google Cloud Storage, S3-compatible services, and the local filesystem. @spfn/storage ships presigned upload, direct and streaming download, server-side copy, prefix listing and cleanup, public URLs, finalization, and deletion — and owns no database. It speaks in object keys, never arbitrary URLs. Uploads have a known correct shape, so your tokens go to the part only you can write.

01
The premise

Six backends.
One interface.

Every provider does storage its own way — GCS signs size ranges, S3 can't; S3 tags temp objects, GCS moves them; local disk supports no presigning at all. @spfn/storage puts one service in front of GCS, S3, R2, Wasabi, and the local filesystem, and documents exactly what each backend enforces instead of papering over the differences. Your app holds the keys in its own schema; the package handles the objects and nothing else.

02
Core technique

The limit lives in
the signature.

A server-side check of a client-declared file size binds nothing — the client can declare one byte and PUT gigabytes to the presigned URL. So @spfn/storage signs the limit into the URL itself: pass maxBytes or contentLength when presigning, and the returned requiredHeaders must be sent verbatim on the PUT, or the signature is invalid and the provider rejects the upload. On GCS the signed range turns any out-of-range upload into an HTTP 400. And where a provider can't enforce, the package won't pretend: S3-compatible presigned PUTs cannot sign a size range, so maxBytes is ignored there — only an exact, signed Content-Length is enforced.

What's inside

The parts you'd otherwise
build again.

providers

GCS, S3, R2, Wasabi, and local disk behind one service.
size-signed uploads

maxBytes / contentLength signed into the presigned URL, enforced by the provider.
temp uploads

temp: true marks unconfirmed uploads so orphans expire by lifecycle rule.
finalize

finalizeObject confirms an upload — idempotent, rejects when nothing was uploaded.
delete

delete(key) is idempotent — a missing key succeeds, real errors reject.
batch delete

deleteMany returns per-key results; S3 batches up to 1,000 keys.
server-side copy

copy(from, to) moves nothing through your app — the source stays put.
prefix cleanup

list and deletePrefix match on the path boundary, so req-1 never eats req-10.
streaming download

getStream serves large private objects without buffering them in memory.
one not-found error

StorageObjectNotFoundError on every provider — one check, three backends.
cdn & versioning

Origin deletion purges neither caches nor old versions — the caveats, written down.
db consistency

A retryable outbox ordering for deletes that span database and bucket.
