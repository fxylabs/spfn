FUNCTIONS / @SPFN/CORE — THE FRAMEWORK KERNEL

The kernel.

Everything an SPFN backend runs on: the HTTP server, the typed route DSL, Drizzle data access, codegen, validated env, background jobs, events, server-owned state, the ops surface, cache, and the Next.js RPC client. The only required package — everything else is opt-in. It is the shape an AI coding agent fills in — the same four files per feature, every time.

02
Modules

Twenty modules.
Documented on-site.

server

HTTP server entry point — config builder and lifecycle.
route

Type-safe route DSL and router composition.
db

Type-safe PostgreSQL data access on Drizzle ORM.
nextjs

Type-safe Next.js RPC client and proxy.
codegen

Route-map generation and custom generators.
env

Schema-validated environment variable management.
config

The kernel's own validated env config.
errors

Serializable HTTP/DB error classes, cross-boundary.
middleware

Error handling, request logging, proxy-guard, rate limiting.
event

Pub/sub events over SSE and WebSocket, with subscribe grants.
job

pg-boss background jobs, typed payloads.
cache

Singleton Valkey/Redis connection, graceful-degrading.
logger

Zero-dependency structured logger, child loggers.
security

Safe outbound requests — SSRF-hardened safeFetch.
state

A server-owned state declared once, kept in sync in the browser.
contract

Route contracts and the build gate for separately shipped clients.
ops

The operations surface spfn ops discovers and runs.
surface

A command surface on any namespace, beside /_ops.
authz

Ownership guards — load a resource, check it belongs to the caller.
app-config

Reads spfn.config.js — the app's ports and host, in one place.
